# R5.3.1 — Kaggle CLI Training Deployment

Automated local-to-Kaggle deployment for CropFusion multimodal training.

## 1. Kaggle Authentication

The launcher requires Kaggle CLI authentication. Supported mechanisms:

```powershell
# Option A: Login interactively
kaggle kernels --help   # verify CLI is installed
kaggle config view      # check current auth status

# Option B: Set environment variable
$env:KAGGLE_USERNAME = "your-username"
$env:KAGGLE_TOKEN = "your-api-token"

# Option C: Use the default credential file
# Location: ~/.kaggle/kaggle.json
```

**Verify authentication:**
```powershell
python scripts/kaggle_r5_3.py check
```

The `AUTHENTICATION` row will show `PASS` if credentials are configured.

**Never hardcode credentials** in scripts, notebooks, or config files. Never commit `kaggle.json` to git.

## 2. Kaggle CLI Installation

```powershell
pip install kaggle
kaggle --version   # Expected: 2.2.4+
```

Key commands used by the launcher:

| Command | Purpose |
|---------|---------|
| `kaggle kernels push -p <folder>` | Upload and run a notebook |
| `kaggle kernels status <owner/name>` | Check execution status |
| `kaggle kernels output <owner/name> -p <dir>` | Download output files |
| `kaggle kernels logs <owner/name>` | View execution logs |
| `kaggle kernels files <owner/name>` | List available output files |

## 3. Project Configuration

The launcher reads configuration from:

| Source | Value |
|--------|-------|
| `KAGGLE_USERNAME` env var | Kaggle username |
| `~/.kaggle/kaggle.json` | Fallback authentication |
| `training_manifests/crop_supervised_v1_manifest.json` | Frozen corpus manifest |
| `govt_crop_matched_v1/crop_supervised_v1.csv` | Frozen corpus data |
| `training/kaggle/notebooks/R5_3_train.ipynb` | Training notebook |

Default kernel slug: `<username>/cropfusion-r5-3-train`

## 4. GPU Configuration

The training notebook:

1. Detects the available GPU at startup
2. Installs PyTorch with CUDA 12.6 support (for P100/T4 compatibility)
3. Runs a tiny CUDA tensor operation to verify GPU works
4. Stops training if CUDA is unavailable

The `--accelerator` flag can be passed to `kaggle kernels push` for GPU selection.

## 5. Dataset Attachment

The notebook clones the CropPrep repo from GitHub at runtime. The large satellite imagery dataset is accessed through Kaggle's mounted input path:

```
/kaggle/input/crop-yield-forecasting-karnataka-dakshina-kannada/
```

The launcher never downloads the ~120GB satellite dataset locally.

## 6. First Training Submission

```powershell
# Step 1: Verify prerequisites
python scripts/kaggle_r5_3.py check

# Step 2: Prepare deployment directory
python scripts/kaggle_r5_3.py prepare

# Step 3: Push to Kaggle (starts execution)
python scripts/kaggle_r5_3.py push

# Or combine all steps:
python scripts/kaggle_r5_3.py train --confirm
```

## 7. Monitoring

```powershell
# Check status
python scripts/kaggle_r5_3.py status

# Or watch in real-time from the launcher:
python scripts/kaggle_r5_3.py train --confirm
# (polls every 30 seconds by default)
```

Configure polling interval:
```powershell
python scripts/kaggle_r5_3.py train --confirm --poll-seconds 60
```

## 8. Downloading Outputs

```powershell
# Download after training completes
python scripts/kaggle_r5_3.py output

# Verify downloaded artifacts
python scripts/kaggle_r5_3.py verify-output
```

Outputs are stored in `artifacts/r5_3/<timestamp>/`.

## 9. Troubleshooting

| Issue | Solution |
|-------|----------|
| `AUTHENTICATION: FAIL` | Run `kaggle config view` or set `KAGGLE_USERNAME`/`KAGGLE_TOKEN` |
| `KAGGLE CLI: FAIL` | `pip install kaggle` |
| `NOTEBOOK: FAIL` | Run `prepare` first |
| `CHECKSUM: FAIL` | Frozen corpus has been modified — restore from git |
| Push fails | Check `kaggle kernels status` for error details |
| GPU unavailable | Verify your Kaggle account has GPU access enabled |
| Training fails | Run `python scripts/kaggle_r5_3.py output` then check logs |
| Timeout | Increase `--timeout` (default 7200s) |
