# CropFusion 2.0.0 - Release Notes

**Date:** 2026-08-15
**Version:** 2.0.0 (see [VERSION](../../VERSION))
**Release artifacts:** `releases/v2.0.0/` (and `releases/latest/`)

## What's new

CropFusion 2.0.0 ships a freshly trained model from the **Dakshina Kannada
dataset stage** (`cropfusion-train-dk-bridge`, Kaggle run completed
2026-08-14). The checkpoint was exported to TorchScript and ONNX and assembled
into the Prediction Platform's `cropfusion_release-v2.0.0/` package.

### Training highlights

- **Source:** `gojosensa/cropfusion-train-dk-bridge` (Kaggle).
- **Accepted observations:** 275.
- **Epochs:** 26 (best epoch 11, early stopped).
- **Evaluation (test split):**
  - yield RMSE: 0.00421
  - yield MAE: 0.00369
  - yield MSE: 1.77e-05
  - crop classification metrics: not computed this stage (`crop/support = 0`,
    masked crop loss) - see Known issues below.
- **Feature order:** Area, Rainfall, Temperature, Humidity, price
  (`input_dim = 5`).
- **Crop classes (5):** Coconut, Blackgram, Coffee, Cardamum, Pepper.

## Known issues

- **Partial release package:** the 2.0.0 release is `valid=False` - the
  train-side `release_sources/` did not include the dataset metadata snapshots
  (`metadata.db`, `historical_context.parquet`, `location_index.parquet`,
  `village_metadata.parquet`). The Dataset Manager reported `INF-DS-001:
  no metadata.db; generate metadata first`, and village metadata was skipped
  because there is no `location_index.parquet`. The package contains the model,
  preprocessors, configs, manifest and metrics (8 files); the 4 metadata files
  must be generated and added before the package can be consumed by
  `ReleasePackageLoader` in strict mode.
- **Crop classification head** produced no validated metrics this stage
  (masked crop loss; `crop/support = 0`); yield regression metrics above are
  the authoritative quality signal for 2.0.0.
