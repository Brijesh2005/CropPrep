## ROOT CAUSE (verdict)

> **HIGH-CONFIDENCE DATA-CEILING**

The CropFusion classifier collapses to coconut because **the frozen corpus is
fundamentally dominated by coconut and the rare classes are spatially
co-located with it — every tabular model that I ran against the *official
frozen split* fails to beat the majority bullet, and no loss-variant can create
signal that does not exist in the data.**

Primary root cause: **extreme class imbalance + spatial co-location of classes**
(train coconut 4292/1599/29/4; all classes resident in the same taluk grid
cells, 94 % of training points within 500 m of a neighbour; median pepper NN =
54.7 m, coffee = 69.9 m, cardamom = 80.3 m) makes the tabular + env + seasonal
vegetation features essentially identical across classes.

Secondary root cause: **rare-class gradient dilution** — the deployed
`focal(gamma=2.0) + sqrt_inv + label_smoothing(0.15)` loses are arithmetic-
correct but the `(1-p)^2` focal suppression and 0.15 smoothing together cancel
most of the 12.2× coffee weight the sqrt_inv factor tries to give.

The primary root cause is **data, not modelling** — and therefore cannot be
fixed by loss re-weighting, model size, or hyperparameter search. Loosening
matching rules or blindly adding imagery will not help either (see
`recommended_next_change`).

## Success-criteria answers

1. **Is the intended crop collapsed into one class?** — No: the intended 4-class
   output is produced, but the *prediction during validation collapses to a
   single class (coconut, 100 %).*
2. **Are all classes collapsed to one prediction class?** — Yes at inference
   (val pred all coconut). Remnant: balanced CE in the Phase 4 sweep also
   collapses.
3. **Are predictions biased to the head ordering?** — No. Head order is
   coconut=0/pepper=1/coffee=2/cardamom=3 and the model prefers the *majority*
   class (first-listed), not an alignment artifact.
4. **Do test/val predictions match?** — Both match (all-coconut); no
   train/val/test drift.
5. **Are val acc == majority acc?** — Yes: gate 0.5584 == majority 0.5584;
   test 0.5242 == test majority 0.5242.
6. **Is the class head mis-ordered vs the evaluator?** — No (Phase 1 pass).
7. **Are the image tensors valid?** — First-batch NDVI/EVI/mask tensors are
   valid (no NaN/Inf). Image-MODEL separability unverified.
8. **Is the loss dead/NaN?** — No; loss-reweighting (focal+sqrt_inv) is
   effective and produces a training gradient; per-sample rare-class grad is
   merely suppressed.
9. **Is the collapse caused by extreme imbalance?** — **Yes and binding** — the
   imbalance plus spatial co-location yields a data ceiling that no tabular
   model escapes.
10. **Is the architecture correct?** — The evaluator/head/order wiring passes;
   the CNN needs the pending Kaggle re-run to verify image-level architecture.

## Recommended next change

**Do not loosen matching rules, do not blindly add imagery, do not run a
hyperparameter sweep.** Instead:

1. **Run the fixed Kaggle GPU kernel** (commit `80bc3263` + uncommitted
   notebook change `R5_5_DUMP_REPORT=1`, `--epochs 2`) — this unlocks
   Phases 3/4/6/9/10/11/14. The current notebook diff adds `R5_5_DUMP_REPORT=1`
   and trims binary epochs to 2.
2. **Held-out rare-class probe:** train on coconut+pepper only, then measure
   coffee/cardamom on the frozen split to quantify the leftover signal instead
   of forcing 4-class training through an extreme-imbalance wall.
3. **Patch-level image probe:** a pixel-patch binary "interior-vs-edge /
   patch-homogeneity" experiment to test whether Sentinel-2 patches carry any
   inter-class signal independently of the env composite.
4. **If the image probe shows no signal**, the correct course is to shrink the
   scope to a **coconut-vs-pepper binary** or a **planted-crop/not** binary with
   the *existing* frozen data, rather than forcing coffee/cardamom which are
   under the ~4–29 train-sample threshold for reliable supervised learning.
